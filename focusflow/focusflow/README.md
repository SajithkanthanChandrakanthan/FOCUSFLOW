# FocusFlow

A lightweight task and habit tracker for remote/hybrid workers who juggle
scattered to-do lists and habit trackers across too many apps. FocusFlow
brings both into one dashboard.

## Product category
Productivity and workflow tools.

## User need
Remote workers often track tasks in one app and habits/routines in another,
losing the sense of "how is my day actually going." FocusFlow combines a
task list and a habit-streak view in a single, fast, distraction-free
interface.

## Tech stack and why
Vanilla HTML, CSS, and JavaScript (no framework, no build step).
For a scoped, four-view application like this, a framework's overhead
(bundlers, virtual DOM, tooling) isn't justified — but the app still
demonstrates component thinking: markup is generated by small, reusable
render functions (see `js/components/`), and a single state store drives
every re-render, the same core pattern frameworks like React formalize.
This keeps the project runnable by simply opening `index.html`, which
matters for a grader checking the work quickly.

## Folder structure
```
focusflow/
├── index.html              # Shell + component mount points
├── css/
│   └── styles.css          # Design tokens (light + dark) and all styling
├── js/
│   ├── state.js            # Central store (pub-sub), schemaVersion 2, seed + migration
│   ├── router.js           # Route name -> view renderer lookup
│   ├── app.js              # Entry point, re-renders on every store change, restores focus
│   ├── utils/              # Pure helpers: dates, habitStats, taskStats, colors, dom
│   ├── components/         # Reusable, view-agnostic UI pieces
│   │   ├── icons.js  navbar.js  datePill.js  popover.js
│   │   ├── habitTracker.js  habitModal.js  taskModal.js  sidePanel.js
│   │   └── taskCard.js  progressRing.js  toggle.js  modal.js  toast.js
│   └── views/              # One file per screen, composed from components
│       ├── dashboard.js  habits.js  tasks.js  reports.js
│       └── settings.js  login.js
```

## Reusable components
1. **NavBar** — floating sidebar card on desktop, bottom tab bar under 720px.
2. **HabitTracker** — week strip + habit-by-day table, used on the Dashboard and Habits views.
3. **TaskCard** — task row with due text and category colour (Tasks view, login preview).
4. **Modal** — one dialog shell for the habit form, task form and delete confirmations.
5. **Toast**, **Toggle**, **ProgressRing**, **DatePill**, **Popover**, **Icon**.

## Accounts and data
There is no server, so accounts live in the browser's `localStorage` (see `js/auth.js` and `js/state.js`).
Each account has its own habits, tasks, settings and theme, so a new sign-up starts with a clean sheet
and two users on one browser never see each other's data. Passwords are never stored: an account keeps
a random salt and a PBKDF2-SHA256 hash (Web Crypto), and sign-in re-derives and compares it.
Because storage is per browser, an account exists only on the
device where it was created; sharing accounts across devices would need a real backend.

## Design system
Colors, spacing, radii, and fonts are defined once as CSS custom properties
in `:root` (see top of `css/styles.css`) rather than hard-coded per
component, so the palette or spacing scale can change in one place.

## Responsive behaviour
- 1200px and up: content column plus a fixed right column.
- 900-1199px: the right column moves below and becomes a 2-column card grid.
- Under 900px: single column. Under 720px: bottom tab bar, 2x2 stat cards,
  a scrolling week strip and one check circle per habit (the selected day).

## Running it
No build step. Open `index.html` in a browser, or serve the folder with
any static server, e.g. `npx serve .`
